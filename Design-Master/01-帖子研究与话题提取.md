## 研究方法与边界

### 计数单位

将一个有独立命题、方法或案例的原创帖/线程视为一个主题单元。线程中的补充帖合并到同一主题；纯回复、寒暄、生活碎片和单纯转发不作为独立设计方法主题，但在账号内容结构里保留为旁支。

### 证据等级

- A：公开帖子页或公开镜像直接呈现完整正文。
- B：账号时间线直接呈现正文，但缺少原始 X 帖子 ID。
- C：搜索引擎摘要、第三方镜像或关联公开仓库中的可核验内容。
- D：根据多条内容归纳出的推断，只用于方法论，不写成账号原话。

- 另一镜像复核：TwStalker 的账号页能在 Edge 中显示状态 ID、正文和 `Load More`；连续加载时同一页的总条目数从 287 变为 372、再变为 440，最后回到空白，属于动态缓存/分页异常。它适合补找公开状态链接，不适合证明 3,589 条活动已经全部读取。
- 分栏关系：`Articles`、`Videos` 和 `Reposts` 中的链接会与 `Posts` 或引用对象重叠；合并后得到 1,614 个原始状态链接，但这不是 1,614 条独立原创帖的计数。
- 去重方式：以 `x.com/yanliudreamer/status/<id>` 为主键；同一帖子在不同快照中的重复出现只保留一条。
- 内容类型：正文、引用帖、回复式短帖和转发评论分开理解；纯寒暄、情绪和单句互动不强行抽取成设计原则。

## 主题索引

### T01｜建立审美灵感库

- 主题：通过 Mobbin、Godly、Lapa Ninja、Minimal Gallery、Dark Design、Refero 等网站进行日常视觉输入。
- 核心命题：审美训练需要持续、可检索的参考源；不同网站分别对应落地 UI、网页风格、Landing Page、极简、暗色和 B 端设计。
- 设计抽取：把“找灵感”拆成输入类型，而不是无目的浏览。
- 证据：S2，置顶帖及其前置帖；S9 中 2026-06-02 的 Mobbin 帖子 `2061600037256458469`；等级 A/B。

### T02｜审美不是感觉，而是设计语言

- 主题：小红书曾分享“设计百科全书”，整理 60+ 种常见设计风格。
- 核心命题：粗野主义、毛玻璃、新拟态、极简、极繁等风格可以继续拆成可理解、可复用的设计语言和提示词。
- 设计抽取：风格名称只是入口，真正可迁移的是色彩、空间密度、字阶、材质、构图、动效和语气。
- 证据：[第三方时间线摘录](https://twstalker.com/futurewatchlog)；S9 中 2026-07-16 的帖子 `2077547687436792185`；等级 B/C。第三方来源只用于确认主题，不作为完整原文替代。

### T03｜用配色参考降低 AI 设计的不确定性

- 主题：推荐 Color Hunt 作为简单直接的配色来源，可把组合交给 AI 参考。
- 核心命题：当设计者无法快速描述配色时，先提供一个具体的色板比空泛地说“高级一点”有效。
- 设计抽取：让参考图或参考站点承担部分描述工作，再由设计者判断是否适合语境。
- 证据：[公开转发记录](https://twstalker.com/learnku)；S9 中 2026-08-19 的帖子 `2089944420535910649`；等级 B/C。

### T04｜Mono-color：把一套视觉判断封装成 Skill

- 主题：Mono-color Skill 不是简单的单色滤镜，而是一套编辑设计语言、复古印刷质感和克制规则。
- 核心规则：默认一色，必要时克制地使用双色；有意识的留白；强 Typography 和编辑排版；网点、颗粒、套印偏移；重新组织图片、文字和版式。
- 使用场景：活动海报、社交媒体配图、品牌探索、音乐/播客封面、Zine/Editorial、照片再创作和 Moodboard。
- 设计抽取：把审美写成颜色、字体、构图、风格和组件等机器可读约束，才能稳定复用。
- 证据：S2、S3、S7；S9 中 2026-08-30 的 GitHub 帖子 `2093968955950150059`、应用场景帖子 `2093968800316293400` 和包装设计帖子 `2094017291297997107`；等级 A/B。

### T05｜AI-native 是一种思维模型

- 主题：AI-native 产品不是传统软件加一个 AI 功能，而是从第一天以 AI 为核心驱动力。
- 核心命题：
  1. 重新定义 Problem，而不是只优化 Solution；
  2. 设计人、系统和 Agent 的新协作关系，明确何时主动、等待、建议、沉默和交还决定权；
  3. Context 成为新的 Interface，要持续回答用户是谁、发生过什么、AI 知道什么、还缺什么以及如何获得；
  4. 设计者需要展示独立 build 能力与新的工作流，而不只是会使用工具。
- 设计抽取：AI 产品设计的基本单位从“页面”扩展为“目标—上下文—行动—控制—反馈”的协作系统。
- 证据：S2 时间线中的 AI-native 原帖；S9 中 2026-08-27 的帖子 `2092835632460796198`，以及 2026-06-24 的面试跟进帖 `2067041454871187585`；等级 B。

### T06｜从想法到作品集网站

- 主题：面向零基础用户的个人作品集快速搭建流程。
- 流程：选项目 → 用 AI 把想法整理成产品需求 → 用 AI Coding 工具实现 → 定视觉风格 → 上传项目/经历/案例 → 调试体验 → 买域名上线。
- 核心命题：个人网站不是一次性简历，而是把经历、想法和作品沉淀成长期资产的名片。
- 设计抽取：先定义要展示的内容，再决定视觉和技术；不要一开始就陷入装饰细节。
- 证据：S2、S8；S9 中 2026-05-29 的作品集帖子 `2060166329152438727`；等级 A/B/C。

### T07｜作品集要呈现工作流，不只呈现成品

- 主题：面试和作品集重做，以及如何在作品集中展示 AI-native 能力。
- 核心命题：项目本身之外，还应展示如何快速把想法变成 Demo、如何与后端工程师衔接、如何做判断和迭代。
- 设计抽取：过程证据能把“我会设计”变成可观察的决策链。
- 证据：S2 时间线中的面试/作品集内容，S8；S9 中 2026-08-26 的帖子 `2092590385646252244` 和 2026-06-04 的 Three.js 作品集动效帖子 `2062335871429550338`；等级 B/C。

### T08｜Product Teardown：产品是系统，不是一屏界面

- 主题：Product Teardown Skill 用 Principal PM 视角逆向工程产品。
- 报告结构：产品快照 → 用户与 JTBD → 核心循环 → 架构 → UX 质量 → 商业模式 → 增长 → AI 就绪度 → 摩擦 → 机会 → PM 终评。
- 五条关键原则：结构胜过观点；循环胜过 feature；AI 位置是 Assistive/Embedded/Autonomous 光谱；截图来自产品自身；报告默认双语。
- 设计抽取：先找到产品循环和被替代的方案，再回到界面、商业模式和机会点。
- 证据：S6；S2/S4 中的发布说明；等级 A/C。

### T09｜用视觉化文档提高可读性与复用率

- 主题：Product Teardown 与 offer toolkit 延续同一套视觉语言，输出适合截图、放入 PPT 或打印的报告。
- 核心命题：结构化内容不应该以一大段干巴巴的文字结束；视觉层级本身是知识传递的一部分。
- 设计抽取：把结论、证据和层级做成可浏览的页面，而不是只给一份长文本。
- 证据：[Product Teardown README](https://github.com/yanliudesign/product-teardown-skill/blob/main/README_zh.md)、公开发布摘录；等级 A/C。

### T10｜Vibe Coding：把门槛降到“能做出来”

- 主题：湾区 Builder/Vibe Coding Demo Day。
- 核心命题：当做一个东西的门槛足够低，每个人都可以成为创造者；现场展示的不是抽象想法，而是正在被“搓”出来的 AI 产品和小工具。
- 设计抽取：设计学习和产品验证都要尽早获得真实反馈；Demo 是沟通对象，不是项目终点。
- 证据：S2 时间线；S9 中 2026-08-26 的 Demo Day 帖子 `2092483720146272739`，以及 2026-07-22 的“长文/自媒体是产品分发渠道”帖子 `2079862617406046301`；等级 B。

### T11｜公开学习与内容飞轮

- 主题：关于 X 涨粉、内容方向和跨平台分发的复盘。
- 核心命题：清晰且有辨识度的自我介绍、记录学习过程、允许粗糙真实、及时分发产品、保持多维主题，并把 X 与小红书、YouTube 互相转化。
- 设计抽取：内容不是一次性交付，而是“创作—反馈—重组—再分发”的循环；真实过程可以成为品牌资产。
- 证据：S4、S2 时间线；S9 中 2026-08-27 的内容飞轮补充 `2092883672399818752`、2026-08-18 的原创奖励拆解 `2093604333367763188`；等级 A/B。

### T12｜Skill 是设计判断的可复用容器

- 主题：从推荐别人的 Design Engineer Skill，到制作自己的 Design Skills。
- 核心命题：如果某种判断会重复出现，就值得把它写成 Skill；Skill 不是一段风格形容词，而是触发规则、设计系统、执行流程和质量检查。
- 设计抽取：把“会做一次”升级为“别人也能稳定调用”，同时保留原创性边界。
- 证据：S2、S3、S5、S7；S9 中 2026-07-22 的 `teach Claude a skill` 观察 `2079740772635816090`、2026-07-17 的 Design Engineer 资源推荐 `2078022962343793007`；等级 A/B。

### T13｜跨主题内容：设计、产品、AI、投资和创造

- 主题：账号并不把自己锁在单一设计垂直领域，而是在设计之外分享产品、面试、AI 时代思考和投资。
- 核心命题：单一主题长期重复会产生审美疲劳；多维内容可以围绕同一个人的判断力形成更大的内容资产。
- 设计抽取：品牌系统可以统一不同主题，但不必让每一条内容长得一模一样。
- 证据：S2、S4；S9 中 2026-08-26 的平台差异帖子 `2092423532831559691` 和 2026-06-07 的平台形式比较 `2063359119957098930`；等级 A/B。

### T14｜投资研究中的“来源—洞见—反方观点”

- 主题：转发长期投资研究工具 Munger Mode。
- 核心命题：从 SEC 文件、财报电话会、播客、博客、内部交易和超级投资者动态中提取洞见，并为每条洞见构造对立观点。
- 设计抽取：研究型产品要让来源、结论和反方观点同时可见；这条是研究方法旁支，不直接等于视觉设计原则。
- 证据：S2 时间线；S9 中 2026-08-29 的美股内容 `2093639911094255862`、2026-08-28 的 `daily-stock-analysis` 帖子 `2093181167487037548`；等级 B。

### T15｜把 Skill 当成完整产品流程

- 主题：从发现问题、定义需求、设计流程、调试，到交付、分发和迭代，Skill 本身就是一次完整的产品实践。
- 核心命题：Skill 的价值不在“会不会写代码”，而在于能否把个人经验沉淀成别人可调用的工作流。
- 设计抽取：为每个 Skill 明确输入、步骤、输出、质量门槛和反馈入口；先做一个小而完整的版本，再迭代。
- 证据：S9 中 2026-08-26 的帖子 `2092511855449354625`；等级 B。

### T16｜Design Engineer：视觉判断要理解实现

- 主题：推荐 Three.js、p5.js、Design+Engineer 公司和设计工程师资源，把视觉、交互、技术和产品构建放在一起学习。
- 核心命题：创意编码不是装饰性技术，而是让设计师能直接试验空间、粒子、Shader、动效和网页交互。
- 设计抽取：选择能直接改变表达方式的技术栈，并用可运行 Demo 而不是概念图证明判断。
- 证据：S9 中 2026-07-21 的 Three.js/p5.js 帖子 `2079384273749242127`、Design+Engineer 公司帖子 `2079480133963194854`；等级 B。

### T17｜用 SOP 降低持续创作成本

- 主题：一次拍摄多条视频、建立长短视频 SOP、在热启动后批量生产内容。
- 核心命题：持续输出不是依赖意志力，而是把高成本动作变成可重复系统；低前期成本比单条作品的精致更重要。
- 设计抽取：把流程拆成准备、生产、复用和发布四段，预先批量处理高摩擦环节。
- 证据：S9 中 2026-07-22 的视频 SOP 帖子 `2079774350077764016`、2026-06-11 的降低拍摄成本帖子；等级 B。

### T18｜数字媒介中的传统设计判断

- 主题：把平面设计多年积累的构图、排版、色彩、留白和节奏带入数字媒介，同时承认有时需要回到 Figma 手工寻找精准感觉。
- 核心命题：AI 和新工具不是对手工判断的替代；工具应该服务于更准确的取舍。
- 设计抽取：先保留设计者对比例、空间和节奏的判断，再决定哪些部分交给 AI 或代码实现。
- 证据：S9 中 2026-07-18 的数字时代平面设计帖子 `2078252348145869033`、2026-07-24 的 Figma 手搓帖子 `2080488248225538559`；等级 B。

### T19｜研究、投资和长期主义作为旁支

- 主题：美股入门、研究工具、投资来源和长期主义，与设计、产品和职业内容并行出现。
- 核心命题：投资内容不是本方法论的设计证据，但它显示出同一种“长期积累、来源筛选、避免随大流”的判断习惯。
- 设计抽取：研究型产品应把来源、推理、反方观点和时间维度同时展示；不能把个人投资表达当成普适建议。
- 证据：S9 中 2026-08-26 的 Kronos 帖子、2026-08-21 的美股文章引用 `2093640139989987350`、2026-06-02 的 AI 创业观点 `2061652906714206684`；等级 B。
