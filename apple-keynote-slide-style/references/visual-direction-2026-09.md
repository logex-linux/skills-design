## 新的设计原则

### 1. 极简不是空白，而是只留一个主语

Hero 页只留一个动作或承诺：大标题、一个主体、一个短 supporting line。背景可以有颜色，但不能有第二个信息中心。标题目标是 3 秒可复述，而不是把所有上下文写进标题。

### 2. 流畅来自状态连续，而不是持续漂浮

参考 Liquid Glass 的设计说明，动效应表现“形态、光线和层级如何从上一状态进入下一状态”：

```text
上一页的色带 / 形状 → 变宽或折叠 → 变成下一页的主体 / 边界
```

HTML 实现用 opacity + 轻微 scale + 有方向的 mask / ribbon；不用弹跳、随机粒子和持续旋转填充空白。普通入口 0.35–0.70 秒，之后留出阅读停顿。`prefers-reduced-motion` 只保留状态显现和顺序。

### 3. 板块必须有内部主题

总结页的每个模块至少包含以下三者中的两项：

- 一个明确标签：问题、重点、例子、待确认；
- 一条具体内容：一句话、一个数字、一个 UI 状态或一个动作；
- 一个视觉证据：高亮、缩略图、轨迹、关系线或可辨识的形状。

如果模块只有边框、渐变和阴影，它是装饰，不是内容板。

### 4. 丰富页要满，但信息密度要分层

建议使用三层：

```text
主层：一个大标题 / 大主体 / 中央结论
次层：3–6 个可扫读的内容模块
底层：短标签、页码、来源或动作提示
```

不要把 12 个同等大小的小卡片铺满屏幕；让中心模块占约 40–55% 的视觉权重，边缘模块负责补充语境。

### 5. 内容层与功能层分离

内容层承载纸张、UI、色块、照片和信息板；功能层只承载页码、章节、按钮或导航。半透明 / 玻璃只出现在需要浮起或强调的功能层，不能让每个内容块都变成玻璃。这样浅色页面既有丰富内容，又不会变成一整面模糊的拟态 UI。

## 新示例的具体处方

以 `大学生起号脚本/01-课程复习卡.md` 为例，8 个 scene 改为以下节奏：

1. Hero：白底 + 大标题 + 一张彩色复习卡，建立承诺；
2. Tension：纸张笔记与复习卡的左右对照，使用一条流动色带连接；
3. Chapter：三步流程用大数字和连续轨迹表达，不做三张深色卡片；
4. Extract：浅色“内容板”，四类信息各有实际标签和高亮；
5. Verify：把 AI 输出、原文、待确认做成证据链；
6. Recompose：四区复习卡，每区填入实际复习问题和内容；
7. Summary：满版复习地图，中心结论 + 四个有主题的模块，提供一次丰富视觉峰值；
8. Close：回到极简提问和轻量输入框，给故事收束。

## 交付判断

这套方向只有在下面四件事同时成立时才算“像发布会”，而不是换皮模板：

- 去掉颜色后，标题、尺度和留白仍然能读出层级；
- 去掉所有边框后，每个视觉主体仍在解释内容；
- 任意连续三页都能看出同一条叙事轨道，但版式轮廓不会重复；
- 动效暂停在任意一帧时，观众能理解元素为什么在这里，以及下一步会去哪里。

以上结论是跨活动观察后的设计推断，不是 Apple 内部规范，也不代表 Apple 官方模板或官方背书。

## 第三轮 QA 结论：把“浅色卡片 UI”继续推向发布会画面

对本案例截图的复盘发现，单纯把深色卡片换成白色卡片仍然会出现“通用 SaaS 模板感”。下一轮实现增加以下硬规则：

- 不让正文从主体后方露出；标题、解释和内容主体必须有独立空间或明确的内部归属；
- 删除不能说明对象、动作或状态的中心 orb；如果需要色彩，色彩附着在纸张、路径、内容板或产品状态上；
- 将多个白卡合并到一个有标题、有中心关系的内容板中；每个子模块至少有标签和具体解释；
- 让内容板成为一个完整的“舞台状态”，而不是四张漂浮卡片；用共享底板、分隔线、色块和层级表达关系；
- 在 8 页中安排空舞台、单主体、流程、证据、内容板和视觉峰值，禁止连续页面只改变颜色而不改变构图；
- 真实验收时除了看静态首帧，还要暂停在转场中间帧，确认每个元素有可解释的来处和去向。

当前示例的第 4 页已按此规则改为“笔记 → AI 辅助 → 四类内容”的完整内容板；相关事件级归纳见 [slide-atlas-2023-2026.md](slide-atlas-2023-2026.md)。
