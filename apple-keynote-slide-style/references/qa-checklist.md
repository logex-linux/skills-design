# Apple Keynote Slide Style：发布前验收清单

这份清单用于在 Keynote、PowerPoint、Figma 或 HTML/Remotion 中完成一套发布会式 deck 后做最后验收。它是模仿 Apple 发布会的设计语言，不是 Apple 官方检查标准。

## 1. 叙事验收

- [ ] 每个 scene 只有一个可复述的主意，标题读完即可知道这一页要表达什么。
- [ ] 开场先建立感受或问题，再给承诺；没有一上来就堆规格。
- [ ] 产品或功能 reveal 前有足够的停顿、留白或视觉铺垫。
- [ ] reveal 后至少有一个真实使用场景、一个可验证的 proof，再进入规格细节。
- [ ] 结尾把“现在能做什么”说清楚，而不是只停留在品牌口号。
- [ ] 从任意连续三页抽看，能判断它们是在推进同一个故事，而不是三张独立海报。

## 2. 画面验收

- [ ] 画布为 16:9；默认制作尺寸为 1920×1080。
- [ ] 重要文字和产品主体位于安全区：左右至少 80px，上下至少 100px。
- [ ] 主标题、产品主体、辅助信息有明确的前后层级；没有多个同等重量的焦点。
- [ ] 使用 12 列网格或同等严格的对齐系统；重复出现的边缘、基线和间距一致。
- [ ] 留白是主动设计出来的，不是因为内容没有排满。
- [ ] 8 页中至少有一页 quiet stage、一页有主题的内容板和一页明确的视觉峰值（满版图像、单一大主体或大尺度 reveal 均可）；密度有峰谷，不是为了数字强行铺满。
- [ ] 执行 70–70：至少 70% 的页面满足 `whitespaceCoverage = 1 - envelopeCoverage >= 0.70`；等价地，8 页 deck 至少 6 页满足 `coverageTarget <= 0.30`。`coverageTarget` 由 `contentBounds.w × contentBounds.h` 推导，不按元素填充面积估算。
- [ ] 低密度页至少保留 25% 连续留白，且主要可见元素不超过 3 组；空白是结构，不是等待填充的区域。
- [ ] 几何检查通过：主视觉顶部与正文底部至少相距 24px（按 1920×1080 预览），标题、正文、卡片、底部说明没有重叠或穿插。
- [ ] 感到拥挤时遵循“先删、再缩、后重排”：先删装饰和重复模块，再缩小主视觉，最后才调整布局；不靠继续加渐变或透明度制造简约感。
- [ ] 每个独立排版元素都有隐藏外接矩形 probe；对停稳后的 headline、supporting copy、primary visual、caption、CTA 逐对执行矩形相交检测，出现相交即不通过。
- [ ] 复合组件继续拆查同层 peer：例如 CTA 文本与圆形箭头、卡片标题与角标、图片与覆盖标签必须各有 probe；仅允许父组与自己的子元素免比较，不允许用“它们属于同一组件”豁免 peer 冲突。
- [ ] 子 probe 必须完全落在声明的父 probe 内；文字从卡片底部溢出、图标从按钮边缘伸出，即使没有与别的元素相交，也判定为失败。
- [ ] HTML 使用 `?collision-debug=1` 显示 probe；PPT / Keynote 使用 100% 透明矩形参与生成期坐标审计；嵌套子元素只在明确声明父子关系时豁免。
- [ ] 按页面顺序完成全量检查：第 1 页至第 8 页逐页停稳、生成 probe、记录结果；不能只检查最后一页。
- [ ] 连续三页没有重复“左标题 + 右漂浮卡片”的轮廓；至少切换一次全版、近景、横向流动或内容板。
- [ ] 标题和正文没有躲到主体、卡片或装饰层后面；主视觉开始前已预留独立的文字空间。
- [ ] 每个 orb、光晕、渐变或玻璃层都在解释对象、动作或状态；无法解释的装饰已删除。
- [ ] 内容板中的每个模块至少包含“标签 + 具体内容 + 视觉证据”中的两项；伪线条和空占位框不算内容。
- [ ] 产品图、界面图和背景效果的光向、透视、尺度关系一致。
- [ ] 视觉纹理服务于产品概念；删除纹理后，主意仍然成立。
- [ ] 不使用 Apple logo、发布会专属图形、产品截图、音乐、演讲视频或未授权字体作为可交付素材。

## 3. 文案与排版验收

- [ ] eyebrow 只提供上下文；headline 承担主要信息；supporting copy 只补充必要解释。
- [ ] 每页正文尽量控制在 1–3 行；长解释拆成 lived demo 或 proof scene。
- [ ] 不依靠极细字重表达“高级感”；正文在投影、录屏和压缩后仍然可读。
- [ ] 英文标题使用统一的大小写策略；中文标题避免逐字硬译导致的长行和拥挤。
- [ ] 同一语义只使用一种颜色，不让 accent color 同时表示按钮、警告、重点和装饰。
- [ ] 数字、单位、大小写、标点和产品名称在全 deck 中统一。

## 4. 对比度与可读性验收

- [ ] 正文、字幕和图表文字在其实际背景上满足至少 4.5:1 对比度；大字或粗体至少 3:1。
- [ ] 检查浅色背景、发光渐变、照片高光和透明材质下的最差区域，而不只检查平均区域。
- [ ] 任何仅用颜色区分的信息都增加位置、标签、形状或文字冗余。
- [ ] 导出后在 100%、75% 和手机小窗预览一次；信息层级不能因缩小而坍塌。
- [ ] 为图片、动态图和复杂产品演示准备简短的 alt 文本或讲解稿。
- [ ] 如果使用动效，提供 reduced-motion 版本：保留出现顺序和状态变化，减少位移、缩放和闪烁。

## 5. 动效验收

- [ ] 动效有叙事作用：建立关系、揭示差异、引导视线或表示状态。
- [ ] 普通入场/转场通常控制在约 0.35–0.70 秒；复杂 reveal 有明确的起止状态。
- [ ] 不使用无意义的弹跳、持续旋转、粒子漂移或镜头抖动来填充空白。
- [ ] 产品主体不会在转场中被遮挡到无法识别；镜头运动与元素运动遵守同一个焦点。
- [ ] 暂停在进入和离开的中间帧时，能解释主体从哪里来、将去哪里；否则改为 cut、mask-reveal 或沿边缘的 morph。
- [ ] 录屏、导出视频和演讲现场的帧率一致；检查掉帧、字体替换和透明通道问题。

## 6. 素材、授权与证据验收

- [ ] 每一张外部图片、图标、字体、音频和视频都有来源、授权和替代方案记录。
- [ ] 研究笔记把“视频或官方页面直接观察到的事实”和“基于观察的设计推断”分开。
- [ ] 规格、价格、日期、系统兼容性等易变事实都能追溯到当前官方页面。
- [ ] 使用第三方复盘 slide 时明确标注为第三方资料，不把它当作 Apple 原始 deck。
- [ ] 没有把“像 Apple”写成“Apple 官方模板”或暗示官方背书。

## 7. 100 分快速评分

| 维度 | 分值 | 通过线 |
|---|---:|---:|
| 叙事推进 | 20 | 15 |
| 焦点与层级 | 20 | 15 |
| 网格、留白、构图 | 15 | 11 |
| 排版与文案 | 15 | 11 |
| 色彩、材质、图像 | 10 | 7 |
| 动效与演讲节奏 | 10 | 7 |
| 可读性与无障碍 | 5 | 4 |
| 来源、授权与品牌边界 | 5 | 4 |
| **总分** | **100** | **≥ 78** |

低于 78 分时，优先修复叙事、焦点和可读性；不要先继续添加装饰效果。

以下任一项出现时，直接视为结构不通过，即使总分达到 78 分也必须返工：

- 正文从主体后方露出或被视觉层遮挡；
- 四个以上同权重白卡没有共享主题、中心层级或关系线；
- 装饰性 orb 是页面唯一的“视觉重点”；
- 总结页只有栏目名，没有具体内容或关系；
- 连续三页只是换色，没有改变画面状态。

## 8. 最终抽查方法

1. **静音抽查**：只看缩略图和前 3 秒，写下每页的主意；如果写不出来，说明视觉层级不够明确。
2. **只听不看**：只听讲稿或演讲录音，检查它是否仍然有清晰的“问题—承诺—证明—行动”顺序。
3. **灰度抽查**：去掉颜色，确认层级由尺度、位置、明度和留白承担，而不是靠彩色硬撑。
4. **最差设备抽查**：在低亮度、压缩视频、远距离投影或手机小窗中检查细字、发光背景和低对比度元素。
5. **陌生人复述**：请没有看过项目的人用一句话复述每个章节；复述与 intended message 不一致时，回到 headline 和 hero visual 重做。
