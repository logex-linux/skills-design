# Apple 近三年旗舰 keynote slide atlas

获取日期：2026-09-02（Asia/Shanghai）

这份 atlas 是从 Apple 官方活动页、官方回放页、Developer keynote 页面、章节时间码和公开画面观察建立的“画面状态索引”。它不是 Apple 的原始 Keynote / PowerPoint 文件，也不是逐帧复制的截图集合。Apple 没有在这些官方页面公开可编辑的原始 keynote 文件，因此这里把视频中的画面转译为可复用的结构、密度和动效规则。

## 研究边界

- 时间窗：2023-09-02 至 2026-09-02，滚动 36 个月；
- 纳入：公开旗舰产品发布会和 WWDC 主 keynote；
- 共 8 场：2023-09、2023-10、2024-05、2024-06、2024-09、2025-06、2025-09、2026-06；
- 不纳入：Platforms State of the Union、技术 session、发布会后的产品新闻稿；
- 画面证据优先级：官方回放画面 / 官方章节 > 官方活动页和产品页 > 跨场推断；
- `observed` 表示能从公开画面或官方页面直接观察，`inferred` 表示跨场归纳后的设计建议。

## 如何使用这个 inventory

1. 先从目标内容选择一个“画面状态”，不要从颜色选择模板；
2. 以章节为单位安排密度：章节 reset 用空舞台，能力说明用 UI / 近景，跨模块回顾才用内容板；
3. 给每个 scene 写一个 `anchor`，让下一页至少继承主体、颜色、边缘、动作或数字中的一个；
4. 只有在素材或内容确实需要时才进入满版视觉峰值；
5. 如果新 deck 连续三页仍然是同一轮廓，回到 inventory 重新选状态，而不是继续换颜色。

## 从视频画面抽出的 7 类状态

这些不是模板，而是每场 keynote 会反复组合的画面状态。最终 deck 应该在状态之间切换，而不是让每一页都长成同一种卡片。

### A. 空舞台 / 单一承诺

- 画面：一条标题、一件主体或一个抽象事件形态；
- 密度：10–20%；
- 用途：开场、章节 reset、结尾余韵；
- 规则：不要额外补充说明，不要把空白填成装饰。

### B. 形体 reveal

- 画面：产品轮廓、局部、侧面、材质或一条边缘高光；
- 密度：20–35%；
- 用途：让对象先被记住，再解释参数；
- 规则：主体占画面 45–85%，标题退到边缘或短暂出现。

### C. 真实动作 / 体验镜头

- 画面：手、人物、设备和 UI 共同完成一个动作；
- 密度：35–65%；
- 用途：把功能变成可感知的结果；
- 规则：每个镜头都回答“谁完成了什么，结果变了什么”。

### D. UI / 证据近景

- 画面：一项真实 UI 状态、一个数字、一个前后对比或一条证据链；
- 密度：25–55%；
- 用途：证明，而不是展示所有功能；
- 规则：不要把完整 UI 缩成一张小卡；先放大关键状态，再补上下文。

### E. 丰富内容板

- 画面：多个模块、产品图、UI、数字和标签组成一个有主题的整体；
- 密度：65–95%；
- 用途：总结、生态、平台家族或能力地图；
- 规则：中心模块占 40–55% 权重，边缘模块补充语境；每个模块必须有内容，不允许只放边框和渐变。

### F. 满版视觉峰值

- 画面：一张满版图片、产品家族、创作场景或色彩事件；
- 密度：80–100%；
- 用途：给观众一次记忆点和视觉呼吸；
- 规则：文字退到最小必要信息，内容主体可以出血，导航和脚注不抢主角。

### G. 安静的行动收束

- 画面：一句 CTA、日期 / 版本 / 价格或一个简短问题；
- 密度：10–25%；
- 用途：让观众知道下一步；
- 规则：把复杂输入表、按钮组和装饰删掉，只留下一个动作。

## 画面密度编排

一套 8 页示例不应 8 页都使用同一密度。推荐的节奏是：

```text
29% → 28% → 28% → 63% → 27% → 28% → 59% → 26%
开场   对比   过程   证据   结构   近景   总结   收束
```

这是一条 `inferred` 的可执行起始值，不是 Apple 内部规范。重点是密度必须有峰谷，且丰富页只在内容需要汇总时出现。

对于本项目的 8 页示例，70–70 约束写成“主要内容最小轴对齐外接矩形”的可验收目标数组。它不是元素像素面积；标题、正文和主视觉组之间的空白也会被外接矩形计入：

```text
[0.288, 0.279, 0.284, 0.626, 0.274, 0.275, 0.592, 0.259]
```

新的 70–70 定义为：至少 70% 的页面保留至少 70% 留白，因此至少 6 页的 `envelopeCoverage <= 0.30`；第 4 页和第 7 页是有主题的内容板，允许形成较大的外围体积。第 1 页仍然是视觉 hero，但收拢为一个小型对象锚点，不再让 hero 卡片把开场横向撑满。覆盖率目标必须从停稳后的完整尺寸截图测量，不能只改透明度或阴影来伪装简约；它的作用是阻止“文本框很大但文字很少”“元素很薄但外围铺满”与“每页都做满”。

## 当前案例暴露出的反模式

截图所示的页面在结构上有五个问题，已加入后续 QA 的阻断项：

1. **标题 / 正文躲在主体后面**：正文不能从视觉主体下方穿出；给标题预留独立空间，或把正文变成主体内部的标签。
2. **装饰性 orb 代替视觉证据**：如果光晕不能解释对象、动作或状态，删除它；颜色应附着在内容上。
3. **所有内容都被做成漂浮白卡**：卡片必须属于一个整体结构；同一页面超过 4 个同权重浮卡时，改成共享底板、色带、拼贴或内容板。
4. **文档线条是伪内容**：`LECTURE NOTES` 下的线条必须对应真实的层级、摘录或高亮关系，否则换成可读短句。
5. **整套 deck 只有一种构图**：连续三页不能都使用“左侧标题 + 右侧卡片”；至少切换一次全版、近景、横向流动或内容板。

## 转场与状态连续性

为每个场景记录 `anchor`，只允许下一场沿用至少一个 anchor：

```yaml
anchor:
  - subject: 当前视觉主语，例如纸张 / 笔 / 复习卡
  - edge: 颜色带、边缘、路径或对齐线
  - action: 提取、核验、重组等动作
  - type: title | object | color | path | number
transition:
  mode: morph | mask-reveal | crossfade | slide | cut
  duration_ms: 420-780
  reason: 为什么下一状态从上一状态演变而来
```

若没有可解释的 anchor，使用干净 cut 或章节 reset，不要用持续漂浮的渐变掩盖断裂。

## 研究限制

- 公开视频常能确认章节和公开画面，但不能证明每一帧由 Keynote、Motion、Final Cut、实时引擎还是合成管线制作；
- 本 atlas 记录的是可观察的视觉结果和设计推断，不声称复原 Apple 的内部源文件、字体、模板或制作工具链；
- 官方视频和页面会因地区、编码和时间变化，实际观察应以当天的官方链接为准；
- 不将 Apple 公开视频、截图、标志、音乐或私有字体作为用户 deck 的最终资产。
